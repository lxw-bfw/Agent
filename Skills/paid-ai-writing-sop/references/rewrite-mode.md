# 改写模式

## 进入条件

用户已经提供原稿，或明确要求改写、重写、升级、润色已有教程。

## 改写前必须先做任务卡

至少补齐这 8 项：

- 主题：这篇教程到底讲什么
- 对象：写给谁
- 平台：公众号 / 小红书 / 知识星球 / PDF / 课程文档
- 目标：读完后用户应得到什么结果
- 时效性：哪些内容容易过期
- 风险点：哪些说法可能旧、错、空、泛
- 可保留资产：原稿里哪些案例、结构、比喻值得留
- 必补内容：缺了什么，导致还不够“付费”

如果受众赛道属于技术向，再额外补 4 项：

- 受众赛道：通用向 / 技术向
- 技术主题细分：`A / B / C / D / E / F`
- 技术栈 / 框架 / 仓库范围
- 原稿有没有缺失版本、目录、调用链、工程权衡

## 改写原则

- 不是保原结构润色，而是保核心信息、重建最优结构
- 允许删除空段落、合并重复信息、前置关键结论
- 优先补读者真正会卡住的步骤、判断和限制条件

## 推荐输出顺序

1. 模式判断：改写已有原稿
2. 文章类型判断
3. 任务卡
4. 原稿问题清单
5. 风格提取与写法策略
6. 新结构
7. 正式成稿

## 改写时必须主动补的内容

- 版本变化导致的风险
- 常见误区和错误理解
- 上手路径或最小闭环
- 适合谁、不适合谁
- 资料来源清单

如果受众赛道属于技术向，还必须主动补：

- 版本、环境、依赖、权限、兼容性说明
- 模块地图、目录树或调用链
- 为什么这样设计，而不是只说结果
- 替代方案和工程权衡
