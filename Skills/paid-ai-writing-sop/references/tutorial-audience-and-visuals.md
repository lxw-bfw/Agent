# 教程受众分层与可视化表达

## 适用条件

当任务同时满足下面两个条件时，优先使用这份规则：

1. 工作模式属于“从 0 撰写新稿”
2. 文章类型属于“教程型”

## 一、教程受众必须先分层

教程不是只分“写给小白”或“写给进阶用户”这么粗。

从 0 撰写教程时，至少要按下面三类受众分层：

### 1. 完全零基础

定义：

- 几乎没接触过这个主题
- 相关术语也不懂
- 不知道目录、命令、配置、角色分工是什么意思

写法要求：

- 先用大白话解释术语
- 先给一个完整案例，再拆解概念
- 不允许跳步
- 每个关键步骤都要写“做完后应该看到什么”
- 优先提供最小闭环
- 能加流程图就加流程图
- 如果没有真实截图或演示图，至少给 Mermaid 图、目录树、表格或伪界面示意

### 2. 用过一点，但仍属于小白

定义：

- 跟着别人用过
- 知道少量术语
- 能模仿操作，但并不真正理解为什么这样做

写法要求：

- 术语仍要解释，但可以比完全零基础更收敛
- 先给完整案例，再讲通用规则
- 重点写“为什么这样做”和“最容易错在哪”
- 仍然需要最小闭环和关键步骤判断标准
- 合适时优先用流程图和简洁示意图减少文字堆积

### 3. 已经入门，想进阶到资深

定义：

- 做过基础实践
- 能独立跑通简单流程
- 想补架构理解、设计边界、工程化方法和高级踩坑点

写法要求：

- 可以压缩基础术语解释
- 重点转向结构设计、取舍、边界、扩展性和维护性
- 要解释“为什么这样拆”“为什么这样分层”
- 对复杂流程、系统调用链、目录组织，优先给 Mermaid 图或结构示意图

## 二、如果用户没有明确受众层级，必须先问

如果当前任务属于“从 0 撰写教程”，且用户没有明确说清受众层级，或说法仍然模糊，必须先问：

```text
在开始调研前，我还需要确认这篇教程主要写给哪类读者：

1. 完全零基础：几乎没接触过这个主题，相关术语也不懂
2. 用过一点但仍属小白：跟着用过，但不真正理解原理和结构
3. 已经入门，想进阶到资深：做过基础实践，想补系统设计、边界和工程化能力

你可以直接回复 1 / 2 / 3，也可以用自己的话描述目标读者。
```

如果用户已经明确说明，例如：

- “给完全零基础小白看”
- “给只会照着点的人看”
- “给已经做过基础开发、想进阶的人看”

则不要重复追问，直接锁定层级并写入任务卡。

## 三、教程型正文必须有一套“可视化判断”

不是每一篇教程都强制塞图，但下面这些位置，优先加入流程图、目录树、表格、伪界面示意或 Mermaid 图：

1. 整体流程有明显先后依赖
2. 有多个角色、模块或目录协作
3. 有“先做 A，再做 B，否则会错”的分支判断
4. 零基础读者容易被纯文字劝退
5. 文章在解释系统结构、调用链、目录结构、安装路径或运行顺序

优先级建议：

1. Mermaid 流程图
2. Mermaid 时序图
3. 目录树
4. 对比表格
5. 伪界面 / 伪输出示意

如果缺少真实截图或演示图，不要硬装有图。此时至少补：

- Mermaid 流程图
- 关键目录树
- “做完后应该看到什么”的输出示意

## 四、教程型内容的案例要求

当受众属于 1 或 2 时，正文优先使用：

1. 一个完整案例把所有术语串起来
2. 再拆解每个部分分别是什么
3. 最后再带读者做第二个案例，帮助迁移到自己的需求

不要一上来就先讲抽象原理、字段定义和架构分层。

当受众属于 3 时，可以改成：

1. 先给结论或结构图
2. 再解释设计取舍
3. 再给进阶案例或复杂案例

## 五、第三方资料的补充要求

高质量第三方资料，不只看英文博客。

如果主题适合中文生态，优先同时覆盖：

- 知乎高质量回答或专栏
- 掘金高质量实战文章
- 阿里云开发者社区文章
- GitHub README、Issues、Discussions、Examples
- 国内知名博主或社区作者的长文教程

目标不是“堆国内来源”，而是补三类信息：

1. 中文读者最常见的理解障碍
2. 本地化环境下的真实踩坑
3. 中文表达里更顺手的案例和解释方式
