# 风格提取表模板

这份模板用于把“参考谁的写法”拆成可执行字段。

不要只说“学歸藏”“学宝玉”，要把风格拆成能真正指导写作的表。

```md
# [文章主题] 风格提取表

> 使用阶段：[改写模式 / 从0撰写模式]
> 受众赛道：[通用向 / 技术向]
> 文章类型：[推荐型 / 教程型 / 方法论型]
> 参考对象：[歸藏 / 宝玉 / 数字生命卡兹克 / 翔宇工作流 / 其他]

如果受众赛道属于技术向，再额外补：

> 技术判断参考池：[Simon Willison / Chip Huyen / Hamel Husain / Andrej Karpathy / Martin Fowler / Thoughtworks / 宝玉 / stormzhang / 其他]

## 1. 标题策略

- 标题更像：[判断句 / 结果句 / 场景句 / 指南句]
- 标题应该强调什么：
- 标题不该强调什么：
- 可直接参考的标题方向：

## 2. 开头策略

- 第一屏优先放什么：[结论 / 纠偏 / 场景 / 结果]
- 开头要先解决什么问题：
- 开头语气应该更像：[老师型 / 实操型 / 判断型 / 场景型]

## 3. 结构推进策略

- 整体推进顺序：
- 每一节之间的关系应该怎么连：
- 哪些内容必须前置：
- 哪些内容适合后置：

## 4. 小标题策略

- 小标题偏：[观点句 / 功能句 / 问题句]
- 小标题要不要带判断感：
- 小标题是否适合直接写结果：

## 5. 术语解释策略

- 优先用什么解释：[定义 / 比喻 / 案例 / 步骤]
- 哪些术语必须解释：
- 哪些术语可以压缩解释：

## 6. 段落密度策略

- 每段大概承载几个判断：
- 更适合短段推进，还是中段展开：
- 哪些地方必须拆成列表 / 表格 / 流程图：

## 7. 边界与误区策略

- 是否主动写缺点、限制、失败场景：
- 最应该前置的误区是什么：
- 哪些边界必须显式说清：

## 8. 结尾策略

- 结尾更适合：[总结 / 动作建议 / 学习路径 / 延伸建议]
- 读者读完后最应该带走什么：

## 9. 这次真正要学的点

- 结构上学什么：
- 表达上学什么：
- 判断上学什么：

如果受众赛道属于技术向，再补：

- 技术判断上学什么：
- 工程边界上学什么：
- 哪些结论必须回到源码 / 官方文档校验：

## 10. 这次不要乱学的点

- 不该模仿的语气：
- 不该照搬的句式：
- 不该套用的包装方式：
```

## 最低要求

如果不想完整填表，至少也要明确下面 8 项：

1. 标题怎么起
2. 开头怎么开
3. 第一屏先讲结论、问题，还是场景
4. 每段平均多长
5. 小标题偏“观点句”还是“功能句”
6. 解释术语时，用定义、比喻，还是案例
7. 会不会主动写缺点、限制、误区
8. 结尾是总结、动作建议，还是延伸阅读
